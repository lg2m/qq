Where the refactor landed

The provider crate now exposes one compiler facade over deep private seams:

  • HTTP exchange depth — http.rs now owns client policy, header safety (SafeHeaders), request execution with pre-stream retry, bounded failure bodies, and wire-limited success streams (HttpExchange). All four HTTP adapters call it; none roll their own transport.
  • One construction authority — construction.rs resolves protocol/auth compatibility and selects the concrete HTTP adapter. HttpAuth is the only public auth-intent vocabulary and EndpointKind is the only Base/Exact representation.

Design principles

Deep modules, thin interfaces

Every extraction must pass the deletion test: it removes repeated implementation from ≥2 call sites, or it doesn't happen. No helper exists for one caller.

Composition over trait hierarchies

docs/design/providers.md explicitly rejects a "generic provider" abstraction that leaks protocol distinctions. Shared behavior becomes functions and small structs the adapters call, not a super-trait the adapters implement.

Make invalid states unrepresentable

Auth/protocol compatibility is checked in exactly one place (construction.rs) and, where cheap, encoded in types so illegal combinations don't need runtime strings in three files.

The interface is the test surface

Contract tests enter at ProviderCompiler::compile → Provider::stream. Private tests remain only for genuinely protocol-local logic (event decode tables, frame splitting).

Invariant for every phase: observable wire contracts, error classification, and secret redaction are unchanged. Each phase lands independently with a green workspace; adapters migrate one at a time (Chat Completions first, Responses last — its Codex path exercises the full seam).

Pattern selection

The classic patterns were evaluated against this crate's actual forces. Several are already present and should be named and deepened; several are deliberately rejected because Rust's ownership and enum model gives a better native tool.

PatternVerdictWhere / why
Facade Keep & deepen HttpExchange is the transport facade over reqwest (retry, limits, redaction). ProviderCompiler is the crate facade — the sole public way to obtain a Provider. Adapter visibility is now crate-private, so the facade is the only door.
Factory Method Keep ProviderCompiler::compile(recipe) → Arc<dyn Provider>. Callers never name concrete adapter types.
Abstract Factory Formalize construction.rs selects a consistent family (adapter + resolved auth + endpoint shape) per protocol from one spec and is the single compatibility authority.
Builder Keep (lightweight) Idiomatic consuming-self builders already exist: HttpProviderRecipe::new(..).with_headers(..), ModelRequest::with_tools/with_system, EndpointSpec::base/exact. No separate XxxBuilder structs — Rust's typed constructors cover it.
Strategy Keep Provider as a trait object is the runtime strategy seam; RequestAuthorizer composes per-request auth strategies (SigV4, request-time bearer/Codex) behind one authorize() call.
Adapter Core of the crate The six provider modules adapt vendor wire protocols to the neutral ProviderEvent model. The refactor makes each adapter only an adapter: codec + stream state + protocol-owned headers.
Bridge Recognize the existing one Protocol abstraction and transport implementation vary independently: Anthropic Messages runs over HttpExchange directly or over Mantle's SigV4-authorized endpoint; Bedrock runs the same neutral model over the AWS SDK. RequestAuthorizer + HttpConstructionSpec are the bridge.
Flyweight Keep Shared intrinsic state: the compiler's two reqwest connection pools reused across every compiled provider; Arc<str> model names; the static AWS HTTP client + config-build semaphore in aws.rs.
Newtype / typestate (Rust-native) Adopted crate-wide credentials::SecretLiteral is used throughout recipe and adapter auth; hand-written secret-bearing Debug implementations were deleted. ByteCounter/StreamLimits follow the same invariant-encoding style.
Template Method Rejected — replaced by composition The classic form (base class with hook methods) would become a ProtocolCodec super-trait — exactly the leaky generic-provider abstraction the design doc forbids. Instead, a shared exchange driver function owns the invariant sequence and hands a plain SseEvent stream to each adapter's local fold loop.
Prototype Rejected Rust's Clone is the prototype pattern. Recipes and the compiler already derive/implement it; a registry of clonable prototypes solves no problem here.
Singleton Rejected (contained statics only) Global mutable singletons are hostile to tests. The two existing scoped statics (AWS client, config-build semaphore) stay private inside aws.rs; nothing else becomes global.
Observer / Decorator / Chain of Resp. Not needed Streams already model event flow; retry/limits are owned inside HttpExchange rather than layered wrappers, which keeps failure semantics in one place.

Final layout

Current state after Phase 5. One file per adapter (per the review: no finer fragmentation, no one-adapter trait seams); shared behavior lives in deep modules the adapters call.

Deduplicate the adapters — shared kit by composition

Done on main 6fe9e3f..5c70c05

Delivered: repeated request exchange, secrets, error interpretation, tool-call attribution, usage accounting, retry-test configuration, and client selection now live behind shared functions and small structs that adapters call.

2a — extend credentials.rs: structural redaction (Newtype)

Updated 2026-08-01: the workspace split introduced exactly the newtype this step called for — credentials::SecretLiteral (redacting Debug, expose_secret()), already public and consumed by qq-auth/qq-config. Do not add a second secret type; adopt this one internally.

  • Adopt SecretLiteral as the secret field type in HttpAuth, BedrockAuth, the per-adapter auth enums, and RequestCredential; delete the five hand-written redacting Debug impls and the byte-identical sensitive_secret_header pair.
  • Add the one shared helper beside it (pub(crate) fn sensitive_header_value(&SecretLiteral) -> Result<HeaderValue, …>: empty-check + HeaderValue + set_sensitive(true)).
  • SecretRef (Env/Stored/Value) stays a configuration-resolution concern owned by qq-auth/qq-config; adapters only ever see resolved literals.

2b — exchange.rs: the shared stream driver (Facade extension, not Template Method)

The four Provider::stream bodies share an identical prologue. Extract it as a function, parameterized by data — not by a trait over adapters:

pub(crate) struct SseExchangeSpec {
    pub messages: ExchangeMessages,        // per-protocol overflow/limit strings
    pub content_type_gate: ContentTypeGate, // Strict | ResponsesCodexException
}

/// Builds the JSON request, executes it through HttpExchange (retry, limits,
/// bounded rejection), gates the content type, and yields decoded SseEvents
/// under StreamLimits. The caller folds events into ProviderEvents locally.
pub(crate) fn sse_exchange(
    exchange: &HttpExchange,
    endpoint: Url,
    headers: HeaderMap,
    body: &impl Serialize,
    sse: SseDecoder,
    spec: SseExchangeSpec,
) -> impl Stream<Item = Result<SseEvent, SseExchangeError>>
  • SseExchangeError distinguishes Rejected(HttpRejection) (adapter interprets its own error JSON via the 2c kit) from transport/protocol errors — so adapters keep ownership of provider error schemas, exactly as the design doc requires.
  • Each adapter's stream() shrinks to: build codec body → call sse_exchange → protocol-local fold loop. The state machines (tool-call maps, reasoning blocks, usage) stay in the adapter files.
  • The Codex missing-content-type exception becomes an explicit ContentTypeGate variant instead of a divergent copy of the gate.

2c — support.rs: protocol-side kit

The kit remains at the crate root until the earned layout move in Phase 5; only then does it become providers/support.rs.

  • Error interpretation: generic api_error<E: DeserializeOwned>(rejection, fallback) -> ProviderError over each adapter's envelope type; shared status_error_kind/value_as_status (currently byte-identical in two files); per-adapter named_error_kind tables stay local.
  • ToolCallLedger<K: Eq + Hash>: the insert-with-reuse-error / get-with-unknown-error / remove-on-stop attribution logic, generic over the protocol's key (item-id, array index, block index). Google's ordinal-synthesized ids keep their local one-shot path.
  • UsageOnce: the duplicate-guarded usage slot + the checked cached-token subtraction shared by all four provider_usage fns (field mapping from wire structs stays per-adapter).
  • Constructor helpers: the identical without_retries() body and the scheme-based build_client/build_direct_client selection.

Migration order & acceptance

  • Delivered order: openai_chat → google → anthropic → openai (Responses last because Codex + request-time authorizers exercise the full driver).
  • Each migration deleted the adapter's local copy in the same commit; the shared kit was then deepened in focused commits.
  • Phase-1 interface tests pass unchanged after each adapter's migration (wire contract preserved).
  • grep finds one implementation each of: content-type gate, api_error scaffold, usage subtraction, tool-call attribution, redacting Debug.
  • No new public items; kit modules are pub(crate).

Collapse the auth ladder — construction as the one authority

Done 4aded08

Delivered: HttpConstructionAuth, HttpEndpointKind, and GoogleEndpoint were deleted. One exhaustive resolve_http_auth table owns compatibility and adapter auth resolution; Mantle supplies its authorizer through a construction-private field.

Design

  • Layer 1 — public intent: HttpAuth stays the recipe-level vocabulary (with Secret fields after 2a). HttpConstructionAuth is deleted; its only delta over HttpAuth — the internal MantleSigV4 variant — becomes a private field on HttpConstructionSpec (an Option<RequestAuthorizer> supplied only by Mantle's construction path). Mantle-only capability is then structurally unavailable to public recipes, instead of being filtered by matches.
  • Layer 2 — resolved auth: one construction-time resolution table per protocol produces the adapter's resolved auth (header name + secret + extra headers + optional authorizer). The four per-protocol enums shrink to what genuinely differs (e.g. Anthropic's x-api-key vs Bearer, Codex's triple header) — or, where an adapter's enum has become isomorphic to "name + secret", replace it with a small resolved-auth struct.
  • One compatibility matrix: resolve_http_auth(protocol, auth, authorizer) and one message table replace the triplicated "requires OpenAI Responses" matches.
  • One endpoint-kind enum: merge compiler::EndpointKind, construction::HttpEndpointKind, google::GoogleEndpoint into one pub(crate) Base/Exact enum defined beside EndpointSpec.

Acceptance

  • Adding a hypothetical new auth intent touches exactly two places: HttpAuth and the construction resolution table (compiler-enforced by exhaustive matches).
  • Exactly one Base/Exact enum and one copy of each compatibility message in the crate.
  • Compiler/construction test suites pass unchanged — they already assert the observable rejections.
